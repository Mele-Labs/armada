kind: tool
name: Walk
---
Write a walk of this change for a person to play against the place it runs. Start from what the author says to try: the description, its How to Test, and the themes of the change. Read the changed code in the checkout to find what the running change draws: the real labels, roles and routes, never ones you guess. Choose a web walk where the change is something a person sees and presses, and an API walk where it is an endpoint with no page to press. Each step shows one thing the change does and says what to look for. Keep the walk short enough to play in a few minutes: the steps that prove the change, not a tour of the product.
