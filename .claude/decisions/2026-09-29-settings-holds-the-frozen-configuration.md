# Where does a job's frozen configuration go, if Overview stops holding it?

**Decided 2026-09-29.**

Overview drew the approved proposal — the gates, the tiers, the cost cap, how it
lands — as a reading that never changes once the job is approved. He said
Overview should draw what is happening instead, which leaves the configuration
with nowhere to live. Settings had become the sixth destination the same day.

**Chosen:** **Settings holds it.** A frozen setup is settings. Overview always
shows what needs him.

Before approval Overview says *this needs your approval* with enough of a
summary to act on, which is his own fifth bullet — *"a job that needs review
should show a summary of everything I need to review it."* After approval it is
what is running, what failed, what is waiting on him.

Settings is editable before approval and a reading after, which is his 28 Sep
rule about a field applied to a whole destination.

**Cost he took:** the approval summary on Overview is new work rather than a
move. The proposal board cannot simply slide across — before approval Overview
needs a summary written for deciding, and Settings needs the same values as
controls.

**Where it lands:** the Overview reframe, unfiled. Its other half is
`2026-09-29-overview-leads-with-what-releases-the-most.md`.
