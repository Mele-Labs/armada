# Does a repository need a Keep on this Mac mark beside its place?

**Decided 2026-10-21.** Walking Keep on this Mac, he met it as a checkbox under the place rows, so the same repository showed a place and a mark that could disagree.
A repository's tiles and the person's own `armada.yml` already follow its run memory place, so choosing This Mac keeps everything on this Mac.

**Chosen: drop the mark; the place rows are the choice.** Choosing This Mac keeps a private repository's pieces and runs here, and no operation, table read or refusal says it again.

| Asked | He chose | The cost he took |
|---|---|---|
| A mark beside the place | Dropped | Nothing stops a later pick of a synced folder or bucket, which sends new writes there |
| A place refused while the mark stands | Gone, with `fleet.run_place_kept_here` | A private repository is no longer locked to this Mac |

**What it overrode.** The 19 Oct decision in `2026-10-19-who-sees-each-piece-of-configuration.md`, *A private repository in a synced folder or bucket*, chose a mark that kept a repository on this Mac only.
Written into `docs/design/who-sees-each-piece-of-configuration.md`, *Choosing This Mac keeps a private repository here*.

## What would make this wrong

**That a person picks a synced folder for a private repository without meaning to.**
Nothing refuses it now, and the repository's name and commands reach that folder in the clear.
